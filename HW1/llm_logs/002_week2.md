## Technical decisions made this session

1. **Ticker-level rather than PERMNO-chain signal continuity.** Work1.md §13.3
   says this is acceptable for DJ30; PERMNO-chain bridging (DD→DWDP→DOW) is
   complex and the plan explicitly allows the ticker-level simplification. At
   ticker transition dates, the new ticker lacks enough history for the
   lookback, so those rebalance dates temporarily have 29 names. `apply_pit_filter`
   prints which dates are short rather than failing silently.
2. **Log-wealth subsetting for non-overlapping holds.** For H4 and H5,
   instead of using a fixed N-day rolling window (which would overlap on short
   weeks or short months), I compute daily cumulative log-wealth per ticker,
   subset to rebalance dates, then use `shift(1)` and `shift(-1)` on the
   subset to get exact rebalance-to-rebalance cumulative returns. This is
   robust to early-close days and holiday-shortened months.
3. **H6 uses offset shifts on the full daily panel.** For the 126-day forward
   and 105-day skip-lookback, I shift log-wealth by a trading-day offset per
   ticker, then subset to month-ends. The overlap across consecutive monthly
   rebalances (5 months of overlap) is handled downstream by Newey-West.
4. **Bonferroni threshold.** `bonferroni_threshold(12, 0.05)` returns 2.8653.
   Headline-table Winner column returns "N.S." when neither family clears
   that threshold in absolute t.

## Bugs caught and fixed this session

### B1. Transition-day PIT mismatch (H3)

- **Symptom.** Strict assertion `(count == 30).all()` failed on 3 dates
  (2017-09-01, 2019-04-02, 2020-04-03).
- **Diagnosis.** These are all DJ30 ticker-change dates. On 2017-09-01 DWDP
  has no prior ret (under ticker DWDP) → signal is NaN. Similarly DOW on
  2019-04-02. UTX on 2020-04-03 has no next-day ret under ticker UTX (we
  already patched CRSP to relabel it back to UTX, but `groupby('ticker').shift(-1)`
  crosses the ticker boundary into RTX).
- **Fix.** Changed `apply_pit_filter` to a printed-then-tolerated model. It
  prints offending dates/counts and asserts `short_days ≤ max_short_days`
  (default 10, 30 for H6). Matches Work1.md §13.3 ticker-level tolerance.

### B2. H6 has 21 short rebalance dates

- **Symptom.** `PIT broken: 21 short days > tolerance 10`.
- **Diagnosis.** Structural, not a bug. The 126-day lookback means every
  ticker introduced mid-window (DWDP, DOW, RTX, CRM, AMGN, HON) has 6 months
  of missing signal after its membership-start date. Counting those
  transitions, up to ~24 short months in the 10-year window. 21 is within
  that envelope.
- **Fix.** Raised `max_short_days` to 30 for H6 only, with an inline comment
  pointing to Work1.md §13.3.

### B3. Nested f-string backslash-escape syntax error

- **Symptom.** `SyntaxError: unexpected character after line continuation`
  in `headline_table.py` inside a nested f-string with escaped brackets
  (`f'{int(r[\"n_obs\"]):,}'`).
- **Fix.** Extracted the `n_obs` formatting to a separate variable before
  the row-assembling f-string.

### B4. LaTeX `%` not escaped

- **Symptom.** MDD values like `-42.3%` rendered raw would break LaTeX
  compilation (`%` starts a comment).
- **Fix.** Added `for_latex=True` to `_format_percent()`; escapes `%` → `\%`
  only in the LaTeX code path.

would look borderline-significant, but NW correction for the 5-month overlap

Bonferroni t\* ≈ 2.87.

H3 turnover ≈ 1.33 per day × 1.5 bps × 252 ≈ 5% annualized cost drag — eats
the thin signal at daily cadence. This will be the cost-sensitivity robustness
exhibit (§8.4).

correction. Whichever two the ICM picks (per Work1.md §10 fallback) will need
to be presented as directionally sensible but statistically unconfirmed —
